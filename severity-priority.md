# Severity vs Priority 🧪

## What is Severity?

Severity describes how much a defect affects the functionality of the application.

### Severity Levels

| Severity | Meaning | Example |
|---|---|---|
| Critical | Application cannot function or crashes | Application crashes after login |
| High | Major functionality is not working | Payment cannot be completed |
| Medium | Functionality is affected but workaround exists | Search gives incorrect results |
| Low | Minor issue with little functional impact | Spelling mistake |

---

## What is Priority?

Priority describes how quickly a defect should be fixed.

### Priority Levels

| Priority | Meaning | Example |
|---|---|---|
| High | Fix immediately | Login is not working |
| Medium | Fix in the current release | Search filter has an issue |
| Low | Can be fixed later | Minor UI alignment issue |

---

## Difference Between Severity and Priority

| Severity | Priority |
|---|---|
| Describes impact of the defect | Describes urgency of fixing the defect |
| Usually based on technical/business impact | Usually based on business importance |
| Determines how badly the system is affected | Determines how quickly it should be fixed |

---

## Examples

### Example 1

**Defect:** Application crashes when users click Login.

**Severity:** Critical  
**Priority:** High

The application cannot be used, so the impact and urgency are both very high.

### Example 2

**Defect:** Company logo has a spelling mistake on the homepage.

**Severity:** Low  
**Priority:** High

The functionality is not affected, but the company may want the branding issue fixed immediately.

### Example 3

**Defect:** Minor alignment issue on an internal admin page.

**Severity:** Low  
**Priority:** Low

The issue has very little functional or business impact.

## Key Point

**Severity = How badly the defect affects the application.**

**Priority = How quickly the defect should be fixed.**
